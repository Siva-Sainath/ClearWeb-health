# Deploying Clearweb Health (Free Tier: Vercel + Render)

This guide walks through deploying Clearweb Health on free-tier cloud infrastructure using **Vercel** (Frontend) and **Render** (Backend API), with scheduled scrapes running in **GitHub Actions (CI)**.

---

## 1. Architecture Overview

| Component | Platform | Configuration / Notes |
|---|---|---|
| **Frontend** (Next.js) | [Vercel](https://vercel.com) | Root Directory: `frontend`, calls Render backend via `NEXT_PUBLIC_BACKEND_URL` |
| **Backend** (Express API) | [Render](https://render.com) | Node Web Service defined via `render.yaml` in repo root |
| **Scraper** (Python) | GitHub Actions CI | Scheduled jobs (`scrape-daily.yml`, `watcher.yml`) populate SQLite / cache |

> [!NOTE]
> **Scraper Execution on Free Tier:**
> Live Python scrapers do **NOT** run on the free-tier Render or Vercel instances due to memory, CPU, and execution timeout limitations.
> Instead, GitHub Actions CI runs the scheduled scraper batches, and the backend application serves price search results via cached queries (`/api/prices/query` and cached SQLite database).

## 2. Backend Deployment on Render

### Step 2.1: Deploy using `render.yaml` Blueprint

1. Log in to [Render Dashboard](https://dashboard.render.com).
2. Click **New +** → **Blueprint**.
3. Connect your GitHub repository (`scrapeverse_project` / `clearweb_health`).
4. Render detects [`render.yaml`](file:///Users/siva/Documents/scrapeverse_project/render.yaml) and creates the `clearweb-health-api` web service with:
   - **Build Command:** `cd backend && npm install`
   - **Start Command:** `cd backend && node server.js`
   - **Plan:** `free`
   - **Health Check Path:** `/api/health`

### Step 2.2: Configure Render Environment Variables

In the Render Dashboard for `clearweb-health-api`, under **Environment**, configure the following variables (refer to [`backend/.env.example`](file:///Users/siva/Documents/scrapeverse_project/backend/.env.example)):

| Variable | Value / Description | Required |
|---|---|---|
| `GROQ_API_KEY` | Your Groq API key (TTS Orpheus + STT Whisper) | Yes |
| `TTS_PROVIDER` | `groq` | Yes |
| `STT_PROVIDER` | `groq` or `auto` | Yes |
| `LLM_PROVIDER` | `openai` for hosted Aria (Ollama is local-dev only) | Yes |
| `OPENAI_API_KEY` | OpenAI API key when `LLM_PROVIDER=openai` | If using OpenAI |
| `OPENAI_MODEL` | e.g. `gpt-4o-mini` | Optional |
| `BRIGHT_DATA_API_TOKEN` | Your Bright Data API token (or `BRIGHTDATA_API_KEY`) | Yes |
| `BRIGHTDATA_UNLOCKER_ZONE` | Your Bright Data Web Unlocker zone name | Yes |
| `FRONTEND_URL` | `https://<your-vercel-app>.vercel.app` (update after deploying Vercel) | Yes |
| `WEBCMD_BRIDGE_SECRET` | Auto-generated by Render or custom secret token | Yes |
| `WEBCMD_ENABLED` | `true` | Yes |
| `NODE_ENV` | `production` | Yes |

5. Copy the generated or configured **`WEBCMD_BRIDGE_SECRET`** and note your Render service URL (`https://<render-service>.onrender.com`).
6. Verify deployment by visiting `https://<render-service>.onrender.com/api/health` (should return `{ "status": "ok" }`).

## 3. Frontend Deployment on Vercel

### Step 3.1: Import Project to Vercel

1. Log in to [Vercel Dashboard](https://vercel.com).
2. Click **Add New...** → **Project** and import your GitHub repository.
3. In the project configuration:
   - **Framework Preset:** Next.js
   - **Root Directory:** Edit and set to `frontend`
   - **Build Command:** `npm run build` (or leave default Next.js build)
   - **Install Command:** `npm install` (or leave default)

### Step 3.2: Configure Vercel Environment Variables

Add the following environment variables in Vercel (refer to [`frontend/.env.example`](file:///Users/siva/Documents/scrapeverse_project/frontend/.env.example)):

```ini
NEXT_PUBLIC_BACKEND_URL=https://<render-service>.onrender.com
WEBCMD_BRIDGE_SECRET=<same-secret-as-configured-in-render>
NEXT_PUBLIC_AGENTIC_RESULTS=true
NEXT_PUBLIC_USE_LLM_EXPLANATION=true
NEXT_PUBLIC_SKIP_ONBOARDING=true
NEXT_PUBLIC_DEMO_INSTANT_RESULTS=true
NEXT_PUBLIC_PREFER_LOCAL_STT=false
```

### Step 3.3: Deploy and Connect

1. Click **Deploy**.
2. Once the Vercel deployment completes, copy your production frontend URL (`https://<your-app>.vercel.app`).
3. Return to the Render dashboard and update the `FRONTEND_URL` environment variable to match your Vercel URL to ensure CORS headers permit requests.

## 4. Shared WebCmd Bridge Secret

The WebCmd Bridge allows the Aria agent to coordinate interactions and stream state securely between the Next.js frontend and Express backend.

- Both Render and Vercel must share the identical `WEBCMD_BRIDGE_SECRET` string.
- Frontend API routes (`/api/page-state`, `/api/webcmd-action`) validate this secret header in production.

---

## 5. Scraper & Price Query Pipeline (CI Mode)

Because scraper tasks (browser automation, DOM extraction, and LLM parsing) are resource-intensive, they run in GitHub Actions rather than free-tier web dynos:

1. **GitHub Actions Workflows:**
   - `.github/workflows/scrape-daily.yml` runs scheduled sweeps across targeted hospital systems.
   - Output data is committed to the cache/SQLite database or uploaded as build artifacts.
2. **Backend Serving:**
   - The backend `/api/prices/query` endpoint queries cached results, enabling instant sub-second response times without triggering live Python execution during user requests.
